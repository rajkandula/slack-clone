heywasp

Real-time messaging for people and teams: personal chats, invite-only workspaces, audio and video calls, and a feed, in one Next.js app.

The solution

One app with two clearly separate worlds.

Personal

DMs and personal groups

Start a chat by username. One DM thread per person, never duplicated per workspace.

Workspace

#channels and roles

Private workspaces you join by invite code. Joining puts you in every public channel at once.

Calls

1:1 and group audio and video, screen sharing, add people mid-call.

Files preview inline

PDF, Word, Excel, Markdown, Mermaid, code, CSV and EPUB render in place.

A feed

Posts with an audience, comments, likes, reposts, follows and private accounts.

How it works

One Node server, MongoDB, a bucket, and browsers talking directly for calls.

How it works: one message

Every message gets a number, so delivery is in order and never doubled.

1

Send

POST /api/messages with a client message id

2

Number

Atomic $inc on the chat's maxSeq

3

Store

Insert into messages with that seq

4

Deliver

Each recipient's SSE pass sends rows above its pointer, within 1.5 s

5

Wake

Web push to anyone whose stream is not live

A retry with the same client id returns the stored message. Edits, deletes and reactions come back through the same loop as message_update events; call signals use it too.

Guardrails in the code

You can only reach people you share a workspace with.

Invite-only workspaces

Search, new DMs, group adds, follows, profiles and posts all check for a shared workspace. Joining takes an invite code.

Codes stored as hashes

Emailed codes are HMAC-hashed, single use, 5 guesses, 3 sends per address per 15 minutes.

Uploads never run

Executables are refused, HTML and scripts are stored as plain text, HTML previews are sandboxed.

Moderation in-process

Images are scanned on upload, public text is filtered, and three reports hide a post.
